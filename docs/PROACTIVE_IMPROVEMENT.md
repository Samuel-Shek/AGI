# 主动发现与经核验改进

本入口复用原五分钟固定控制器。它让已批准范围内的功能问题不必等用户投诉才进入修复，不授权模型扩展自身权限，也不代表整台电脑的任意软件都能自动修改。

## 当前范围

- 只检查已登记 AGI 的现有纯文本处理函数：文字块读取、请求正文提取、时间解析。检查只用固定合成输入，不读取新增私人资料。
- 工程候选沿用原四文件名单、纯函数／文字／布局准入、隔离运行、每天一项工程预算、最多两轮候选及账户退避。后台不能修改固定检查、发布器或本说明来获得新的权限。
- 用户反馈优先。后台发现的事项登记为本机系统问题，不伪造成用户投诉或记忆事实。
- 启用入口是受控命令 `proactive-enable`，要求原自主处理、隔离、模型及本次发布验收已成立。暂停与停止继承原控制面；重复启用不重置预算、请求或选择。

## 一项改进的证据

固定检查发现 → 模型给出受限候选 → 旧行为失败 → 候选通过同一固定检查与回归 → 受信基线全套测试、受影响测试隔离复验和签名构建 → T9 最小恢复件核验 → 配套安装 → 当前安装文件、后台恢复与固定功能检查 → 单项通知。

基线全套测试只运行已验收版本，不加载候选代码或模型测试。固定控制器追踪改动函数、源文件读取和子进程依赖，将受影响的固定测试放回候选隔离环境；未能归属的依赖保守复验，测试清单变化、新增跳过或任一失败都不能放行。本机状态／停止服务测试的临时夹具物理排除了所有可自动改动的 Python 文件，原服务启动、重复启动、停止和重启断言继续保留。

候选模型自己的测试不能单独证明修复。固定控制器代码、策略和检查清单不在模型可写范围。合法纯函数修复后的验收衔接，仅允许已经过结构准入的文字读取模块指纹变化，并绑定原验收、候选文件清单、完整测试和当前安装回执；其他控制器字节变化仍需操作者重新验收。

## 失败与不中断使用

- 源码变化使旧候选失效；不覆盖其他任务修改。
- 尚未发出的模型请求可以等待原锁；已经发出的未知请求只能读取原输出，不重发。已完成输出可以续用，不增加模型轮次。
- 候选准备允许在界面使用期间执行。安装只向 AGI 自己发送短期、同进程、同版本的安全退出请求，不对其他程序发信号。
- 安静启动后的 AGI，只有本进程从未发生用户交互、未显示编辑窗口、无可见/最小化/已编辑窗口或对话框时才自行正常退出。任何交互都锁住此许可直至该进程退出；关闭窗口不清除这项保护。旧版应用不支持此协议时保持等待，不强杀。
- T9 不可用、安装结果不明或后台未恢复时，保留原阶段与凭据，不发成功消息；不重置原交易、不用旧数据覆盖新数据。
- 安装后的后台启动不主动弹出主窗口。本人随后仍可正常打开 AGI。

## 通知与验收范围

“AGI 自我进化”群的新消息每次只含一项已验证的功能改进，固定两行：做了什么／为什么做。正文由固定、无私人信息的说明生成，不直接外发模型或历史对话原文。发送前重新读回当前证据；未知旧发送仍核对原请求，不改正文或重发。

一般任务进度保留本机历史。记忆文字变化的既有汇报渠道不变。本次功能检查证明工程行为，不计作自然使用样本。原至少七天、三次独立自然结果的要求及原事项负责人保持；没有自然证据时明确仍在观察，不宣称长期效果已验收。
