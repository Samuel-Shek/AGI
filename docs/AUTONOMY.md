# Autonomous investigation and improvement

AGI 0.9 adds the owner-approved policy `owner-approved-autonomy-20260921` to the existing feedback controller. It is installed by a local operator after verification; classification cannot enable it. The controller retains the existing five-minute schedule, five-item analysis batch, one engineering job per day, two candidate revisions, and persistent account-limit backoff.

## Work and human decisions

`work_items` and append-only `work_events` live in the existing feedback database. A work item binds its kind/reference to the current source revision, project, evidence, processing checkpoint and actual result. States are queued, investigating, waiting_evidence, ready, running, verifying, observing, verified, resolved, human_required and blocked. Source updates invalidate prior processing; in-flight execution must be reconciled before another installation. Pausing does not erase checkpoints.

Legacy technical decisions are superseded with a policy-rerouting audit, without populating human choice or decision timestamps. Explicit human reasons and real answers remain independent. Fixed option_1 through option_3 refer to the current proposal alternatives; saving an option is a receipt of the user's answer, not proof a payment or external action occurred. Unknown targets and missing evidence stay system work. Dismissal is historical exclusion, never a verified repair.

The native decision page counts genuine choices. Autonomous progress, evidence summaries, actual changes and remaining gaps appear in the evolution page. Source mismatch invalidates displayed success; missing status is never zero work. Independent autonomy pause/resume coexists with the existing global stop.

## Memory

The memory worker uses owner-checked candidate/body reads and registered authoritative sources. A separate review-center operator issues automatic_authorizations bound to the source, memory hash, candidate fingerprint, policy, actor and action. Human confirmed_at stays NULL. The existing ledger, source writer and retrieval policy continue to govern actual storage and use. New corrected records use truthful automatic metadata and supersede history instead of overwriting old bodies.

Authority documents or explicit, reviewed claim correspondences are registered by the operator; model output cannot register authority. Age, similarity and unsupported semantic inference do not authorize memory changes. Compound memories preserve valid requirements when replacing an outdated component. Source changes revoke stale automatic active qualification on retrieval, even before the next background tick. Unmatched candidates retain uncertainty and direct-source investigation receipts.

## Local software

Fixed adapters identify AGI and Meeting Assistant using registered roots, repository markers and current source-task evidence. Unambiguous product aliases in a verified owner complaint can select an already registered project; body paths cannot register a repository. Conflicting targets wait for evidence.

Automatic edits are structurally admitted: pure text transforms, declarative presentation and bounded subtitle styling. Controller policy, authorization, credentials, storage effects, networking, build/publish/verification code and migrations cannot be altered by generated candidates. All changed code, regression tests and build tools execute inside OS isolation; the fixed controller owns installation. Other changes remain technical work with a concrete scope gap, not a request for the user to debug.

Candidate acceptance requires actual old-source assertion failure, candidate pass, unchanged project checks, clean source, signing and artifact provenance. Publication rechecks source/app identity and application idleness. It preserves user working changes and data; rollback restores code without restoring an older user database. No remote publication, purchase or credential change is part of this policy.

## Proactive improvement

The fixed `owner-approved-proactive-20261014-v1` policy adds daily synthetic checks to the existing five-minute controller. It checks structured text extraction, request-region isolation and timestamp handling against the installed, matching AGI source. These are explicit functional contracts, not an unrestricted whole-machine scan or permission to rewrite Skills, controller rules or other applications. A source revision is deduplicated; unchanged healthy inputs produce no notification. A failing check creates a personal-system candidate, never a fabricated owner complaint or memory entry.

The existing one-job-per-day engineering budget and two-candidate limit remain shared with user-reported repairs. A model proposes a bounded patch in a read-only workspace. The original behavior must fail both its regression and an independent fixed contract; the candidate must pass both. Generated tests run separately from fixed tests. Full fixed Python suites execute on an immutable trusted baseline, with each test module in a fresh process. Any call/read of changed code, module reload, unknown child process or unscoped dependency selects its entire test module for a fresh isolated candidate process. This retains within-module test order and cached values while preventing cross-module cache leakage. Test inventory, repeated test counts, skips, source manifests, logs and governance helper hashes are bound to the receipt. Swift, interaction, privacy, build and signing gates remain required.

Publication needs a verified recovery package directly on the registered T9 disk, a clean matching source/App/Core pair and an idle native application. The new UI can exit gracefully only after a background maintenance launch that has received no user interaction and has no visible, minimized, edited or modal window. Initial installation on an older UI may need a normal user quit. No forced quit is used. Known temporary failures resume their saved phase; an uncertain model or installation request is only reconciled, never replayed. Snapshot construction records directory identity before checkout and never resets an unknown or completed tree.

After installation, the controller checks the current paired files, restored background runtime and the fixed behavior again. Only then can the existing private evolution group receive one two-line functional notice: what changed and why. Delivery rechecks group membership, destination and the installation proof; duplicate/unknown sends retain their original reconciliation rules. Queue progress remains local. Memory change notices retain their separate route. Fixed-input verification does not count toward the existing seven-day/three-independent-natural-results acceptance requirement.

Failure is visible in the existing work-item state and verification logs; no passing release or success notice is recorded while a gate is missing. Global stop and autonomy pause stop new discovery, model work and installation. Disabling this policy leaves existing records and unknown outcomes intact. Recovery restores the exact replaced code through the paired publication contract and never restores an older user database. Source implementation, operator acceptance, live activation, first installed improvement, external delivery and long-term benefit each require their own evidence.

Finite validation and build children retain the existing serialized maintenance lease, nice level 10, private environment and OS sandbox. Inside that lease, the fixed macOS taskpolicy executable selects an application process type only for the finite child, preventing an inherited launchd Background type from adding I/O delays that invalidate response-time tests. The scheduled controller remains Background; time limits, assertions, model budgets and candidate permissions are unchanged. A failed launcher fails the gate without an unrestricted retry. Test fixtures declare their intended file modes explicitly while the production umask remains 077.

The proactive source guard uses the same finite process type for exactly five read-only Git command forms, retaining every identity check and the original 30-second command deadline. Those reads disable Git's optional index refresh locks, so inspecting status cannot write the index or leave a lock when interrupted. Existing locks remain untouched, and publication's required write locks remain enforced. Other Git callers keep their default scheduling and locking behavior. Source-check timeouts retain a bounded command-kind diagnostic; they still stop the model and preserve an unknown outcome without replay.

A model request with an unknown outcome continues to block the same source. After the original cooldown, only a fresh, accepted, paired App/Core source that differs from the old source can invalidate the old candidate. The controller records the exact supersession separately, preserving the original error, request, attempt count and unknown budget. An existing publication intent takes precedence and is only reconciled. New discovery remains subject to its original daily schedule and budget; supersession is neither a refund, a retry nor a successful repair.

A publication intent is reconciled before any source invalidation. A narrowly proven failure before its first exchange may leave an obsolete candidate blocked after the original cooldown, only when a newer accepted, signed App/Core pair is stable and the candidate is absent from its complete local parent history. The exact private request, preparation, no-new-exchange and restored-runtime records must agree; any exchange, pending preparation, incomplete installation, history ambiguity or live publisher keeps the outcome unknown. The original request, result bytes, settled or unknown costs, daily allowance and attempts stay intact. A separate supersession record is not permission to replay the old publication or edit its candidate. Future publisher errors retain only fixed error labels, controlled code locations and actual process-return metadata in small immutable local records; private output and exception text are never copied into those records.

A proven native publication rollback may change only the original root objects' filesystem change times while restoring their exact inodes, contents and metadata. Same-request continuation can reconcile those times only within the recorded rollback interval, after rechecking the original source, candidate, retained stages, complete member identities and recovery proof. It preserves the exact prior receipts in a separate immutable record; it never rewrites the prepared proof or refreshes a conflicting reconciliation. Unknown transaction states remain blocked. A failed attempt before its first exchange keeps the prior journal intact, and installation/runtime receipts identify the actual controller used. This continuation does not authorize clearing an existing Git lock, replacing data, skipping qualification or replaying an unknown model request.

After a Mac restart renumbers the local device, an operator-qualified transaction that was already fully rolled back before this boot may explicitly revalidate its exact original objects on the current internal APFS Data volume. Every original inode, member, content and attribute must match; only that device number and the already-proven rollback root change times may differ. The current boot and actual volume UUID, unchanged original request/prepared/product evidence, candidate App identity and retained-stage identities are bound in a separate immutable receipt. A legacy proof without a source UUID is not described as having proved an old UUID match. The fixed controller consumes only those exact current identities during this transaction, never a general device-ignore option. Before any new exchange, an exclusive durable pointer binds the exact same-boot reconciliation. A later known rollback revalidates all current objects against that anchor and its new rollback interval. A committed continuation uses that same anchor even if the first installed-receipt write failed; any existing installed receipt must carry the identical reference. A different boot requires fresh investigation. This does not alter the old product qualification or recovery payload, create another backup, refund unknown costs or authorize an unknown transaction replay.

## Learning and result integrity

Verified owner corrections may activate a fixed set of already-authorized execution practices for AGI model calls. Each use rechecks source references; these local practices do not assert that another AI or an already-open session changed. Learning activation, installation, fixed replay and natural improvement are separate states. Natural software improvement still requires at least seven days and three distinct verified samples. Models cannot attest their own improvement.

## Fixed commands

Existing `activity_mvp.feedback.cli status/detail` remain read-only. Operator `autonomy-enable` requires the exact approved policy authorization; `autonomy-sync` and `autonomy-investigate` are bounded controller operations. UI commands `autonomy-pause` and `autonomy-resume` only control already-enabled work. Global pause/stop blocks new reads, models and repair. The shared memory operator is a separate local process with a fixed stdin contract, not an arbitrary-command MCP tool.

The owner-approved conversation policy `owner-primary-conversations-20261016-v1` is separate from memory and delivery authority. It admits only the last fourteen days of authenticated local primary Codex, Claude Code and primary-profile Hermes sessions under registered native sources. Corporate project roots, unknown identities, sidechains and credentials retain their existing exclusions. The operator prepares a private candidate with `tools/configure_conversation_sources.py`; activation requires the matching installed App/Core and current operator acceptance. Revocation shares the existing control boundary, invalidates in-flight reads and submissions, and preserves records. Every reflection call records complete source metadata, including historical discussions and previous insights, before a saved input can be read under this grant. Missing metadata remains unverifiable. No new service, model budget, memory permission or company task is enabled.

Hermes additionally requires native primary-session and project metadata: no parent, the default profile, an absolute working directory and no corporate working/repository root. Missing metadata remains unknown. Read projections recheck this mutable database metadata on every admission rather than caching an allow against the main file's identity, which need not change while its WAL changes.

Implementation and release acceptance must verify source, installed App/Core, external review-center and shared writer, retrieval behavior, persistent jobs and natural observation separately. None of this is a claim of general artificial intelligence.
