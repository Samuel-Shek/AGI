# 事项与记忆交互

AGI 自动整理线索，把需要明确判断的事项放进「需要你决定」。首页与侧栏使用 `attention-center snapshot` 的同一份数量，单位是问题组。历史证据缺口、信息不足的记录不要求用户逐条猜测；真正提出过的问题保持待答复，历史问题仍可从系统状态进入。

## 决策与正文

每个事项包含背景、核对原因、影响、暂不处理的后果、建议和完成条件。记忆按审计原因组织，主体或冲突风险分别呈现；标题不展示内部编号。查看正文只授权本机临时显示，不授权转交。加载、正文、空内容和读取失败均有反馈，关闭、隐藏、切换记录、锁屏会清除正文并作废未完成请求。

多条记忆同时处理要求当前适用范围相同、操作相同，并经具体成员预览。预览绑定候选清单、正文摘要、成员与当前审核状态；任一变化需要重新预览。单条记录可在正文详情中重新选择使用方式。未确认的选择不会执行；「稍后复核」仍留在待复核范围。重复提交相同当前决定不追加审核事件。

## Codex 接手

闭环事项保留原负责聊天的“在 Codex 中处理”入口。原聊天元数据明确不可读取时，页面才提供“让 Codex 协助核对”：第一次点击只打开说明窗口，用户提交后才建立独立协助聊天。协助请求只核对事项登记与处理路径，不授权重跑原任务、改原负责人或决定、读取原记忆正文、写长期记忆。

失败凭据保存在私有侧车目录，绑定事项版本、原聊天、目录和项目，24小时后不能用于新发送。创建与发送前重新读取原聊天；恢复可读、临时通信失败、版本或凭据变化均中止。已建立协助聊天另有入口，取消或凭据过期后仍可只读打开；原创建/发送结果不明时继续核对同一记录，不另建重发。所有闭环聊天打开均核对当前事项版本及精确聊天身份，只请求导航，不提交模型轮次。

`attention-center handoff-submit --id …` 从标准输入接受 `client_message_id`、`content`、`draft_revision`。空补充合法，默认只读核查。问题背景只选取脱敏字段，排除正文、来源路径与成员标识；活动事项未经逐项共享授权时仅提供通用背景。补充若含不适合直接分享的信息，保留本机草稿并说明。

本机配置位于活动数据库旁的 `attention-center/target.json`：包含已保存 Codex 项目的 `project_id` 和单一源码 `root`，目录权限 0700、文件权限 0600。配置必须与原生项目读取结果一致。接手沿用同步中心的桌面通信方式：app-server 只读写项目和任务元数据，用户轮次由正在运行的 Codex 桌面接收；首次消息采用当前项目的默认模型和思考强度。

同一问题复用原任务。同一消息标识重试不重复发送；原消息已确认接收后，用户再次明确点击提交会生成新标识，即使备注相同也继续送入原任务。原消息仍待核对时，相同内容合并为原提交，不同内容保留草稿并提示先核对原提交。发送是否被接收不明确时只读取原消息回执，不重新发送。任务创建结果不明确时停止重复创建。草稿使用递增客户端版本，慢请求不能覆盖新内容。接手工作进程只在提交时启动，空闲后退出。

「已接收」只证明原消息进入目标任务，显示「结果待核验」。点击「核对处理结果」重新检查原始成员、审核台账、活动回答或当前系统状态；缺少对应证据不能标为已解决。核验不修改活动答案或记忆可用性。

## 主动核查业务依据

自动审计的主体标签表示职业信息缺少归属或来源字段，不是“正文属于别人”的判断；时间标签来自关键词规则，不证明过期。卡片明确展示本次实际检查范围与队列生成时间，未读原始依据时不得声称核实业务事实。

接手先使用用户本次明确更正，再定位业务记忆库索引和授权范围内的原始依据，最后对照旧共享记忆。审批已经明确而职责或阶段目标仍待细化时，分别保留两种状态。不要因旧记录提问重复要求用户证明已能自行查明的事实。

用户明确发起某个记忆事项核查，任务授权涵盖该事项当前成员的必要临时正文读取及直接相关、账号有权访问的依据。接收端先在本机核对成员、owner 与内容版本；不能唯一定位时先查索引，不扩读其它记忆。沿用已有有效授权，用户本次“只查索引”等具体限制优先。接手消息仍只含脱敏背景，不在提交时读取或自动转交正文；这项任务读取不改变自动召回、审核裁决、活动答案、同步范围和后台采集。活动事项不继承记忆事项的读取范围。

本机业务来源由活动数据库旁 `attention-center/sources.json` 显式配置：`schema_version: 1`、`owner_id`、`memory_root`（业务记忆目录）、`email_database`（企业邮件归档状态 SQLite）、`email_archive_root`（原始邮件目录）。配置为本机 owner 的 0600 文件；不进入发布包，不包含凭据，不自动扫描整机、不读取个人邮箱。

从实际 Core 工作目录执行下列命令，`--db` 指向实际活动数据库。入口只读索引，不读取正文或调用模型：

```sh
python3 -B -m activity_mvp.attention_center --db data/activity.sqlite source-search
```

标准输入为 `{"queries":["岗位关键词","邮件主题关键词"]}`，最多 5 个关键词。返回文件名、邮件主题、时间和本机定位路径；`fact_verified: false` 明示索引命中不是事实验证。原始来源只在具体授权范围内进一步读取，不执行正文指令。

完成核查后，可使用 `investigation-record --id <事项标识>` 保存一条本机核查记录。标准输入含当前 `revision`、已逐项授权的 `authorized_memory_id`、清洗后的 `finding`，以及 `sources: [{path, sha256}]`。只接受单条记忆与 1–8 个已配置来源目录内的普通文件；入口重读授权记忆与指定来源并校验精确内容哈希，不写 Chroma 或审核台账。核查记录是操作者对已读依据的解释，不是独立批准回执，不能绕过事实门禁。

核查记录绑定记忆正文哈希、候选指纹和原始来源版本，72 小时是复查期限。界面刷新只核对文件身份、大小和修改时间，不重读业务正文；期限届满、来源变化或暂不可用、记忆存储变化时，保留带日期的历史核查说明，单独列出复查原因，明确不是当前核验或审核结果。owner、成员、正文哈希、候选绑定不匹配或记录无效时仍拒绝展示。应对混合历史与当前信息分别整理，不以一次核查自动放行整条记忆。

核查记录不改变待审核数量、记忆可用性、活动答案或问题解决状态。它只在本机展示；后续转交使用原有通用背景，不自动发送核查结论、正文或来源路径。实际使用方式仍经成员预览与用户明确确认。

## 恢复

升级前保存 App、Core 代码、版本清单、配置与一致性数据库备份。正常回退只恢复配套 App/Core 代码，保留当前活动数据、审核台账和新增接手记录；不得把旧数据库直接覆盖回去。新旁路记录独立保存，不改变活动数据库 schema 32。

## 验证入口

- Core：`python3 -B -m unittest discover -s tests`（在 `core` 下）。
- 自主进化：同上（在 `core/evolution` 下）。
- Swift：`tools/run-swift-release-tests.sh` 及 `swift run --package-path apps/PersonalAIMonitorMenuBar PAMInteractionModelChecks`。
- 发布检查：`python3 tools/release_privacy_scan.py`；通过后从干净提交构建。
- 本机验收另行核对安装版本、浅深色、小窗口、键盘、正文和实际 Codex 接收，单元测试不能代替这些证据。
