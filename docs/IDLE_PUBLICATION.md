# 自动更新退出保护

自动更新只在当前输入安全、界面空闲且请求有效时正常退出应用。历史菜单操作不作为退出条件；后台启动参数仅控制启动时是否显示窗口。人工退出的原生流程保持不变。

## 输入与保存

应用主线程统一管理实际表单值、最后确认保存的基线、编辑版本和在途操作。覆盖活动判断与补充说明、手工补记、快速补记、记忆改写及审核选择、事项备注、共享上下文和 Codex 交接草稿。搜索、面板展开及菜单切换不算输入草稿。

关闭窗口、最小化、切页和视图重建均不清除未处理内容。共享窗口复用原编辑器；各表单在进程内保留状态，不新增草稿落盘或后台服务。来源撤回仍遵守原隐私规则：撤去该来源的正文和读回闭包，旧回调不能重新填回已撤去内容。

共享窗口的四处分组使用现有 `AGISectionBox`：标题单独暴露为辅助功能标题，内容仍放在无标题的原生分组中。这样避开具名分组在当前界面工具读取时触发的服务崩溃，保留日期、输入绑定及所有人工操作。隔离对照中，原具名分组读取崩溃，兼容容器可读取、编辑并放弃测试输入；这不替代安装后的真实共享表单及草稿验收。

保存开始前绑定不可变的提交内容及版本。成功只结清对应操作；旧回执不能解除新编辑，连相同文字在另一编辑版本出现也须核对。结果不明确时只沿原入口读取，不自动重提记忆选择、活动判断、补记或消息。确证写前拒绝标为保存失败，允许本人修正后重试。收到精确回读成功后，同步解除原表单的等待状态；只有当前值仍属于该提交时才复位表单。

已有交接草稿自动保存沿用原权限与递增版本，旧写入不能覆盖新版本。关闭页面只补交实际尚在延迟队列中的编辑，纯查看不触发保存。活动重新梳理可以拆分或过滤原问题；在既有事务记录中保留不含正文的提交标记，核对仅证明这次提交已处理，不证明活动判断或证据仍有效。

准备重新梳理活动、撤回共享时，先处理同一记录上其它未提交字段；界面提供明确放弃入口，避免记录消失后留下无法恢复的草稿。取消窗口不等于放弃，放弃也不冒认未确认的保存已经完成。

## 原因与恢复

在既有进化事项中显示固定文案及真实检查时间，不另弹提醒窗口。多个拦截条件独立解除。

| 原因代码 | 原因 | 恢复条件 |
| --- | --- | --- |
| `unsaved` | 还有未保存的内容。 | 完成原表单的保存／确认，或明确放弃后可继续更新。 |
| `saving` | 最新内容正在保存。 | 收到保存成功回执后解除此项拦截，无需重复点击。 |
| `save_failed` | 保存未成功，内容仍受保护。 | 原保存入口重试成功后可继续。 |
| `unknown` | 暂时无法确认最新内容是否保存。 | 系统需先核对保存回执，不会据此强行退出。 |
| `interface_in_use` | 当前界面仍在使用。 | 完成操作并关闭窗口／菜单后重新检查；最小化仍视为正在使用。 |
| 无拦截 | 已具备安全退出条件。 | 等待原更新流程再次核对。 |

应用活跃、展开菜单、可见或最小化窗口、对话框、系统标记的未保存文档都属于当前占用。旧版缺少回执时显示“无法确认退出条件”，不能推断有草稿；此时保留发布端实际检查时间及本次请求关联，明确标为发布端观察，应用实例未知，不冒充原生回执。请求过期和进程尚未退出分别说明原因。

菜单栏图标由 AppKit 创建的内部窗口常驻可见，不能当作正在编辑的窗口。多屏环境还会生成同一图标的系统镜像窗口。退出协调器以当前已登记图标窗口的实际 AppKit 类型为依据，并同时要求状态栏层级、不可成为主／键窗口、没有窗口控制器或代理、内容全为 AppKit 被动图标视图，除已登记的那个图标按钮外无控件，并且无文字编辑器、可获焦点视图或手势，才排除这一项可见性；不依赖私有类名或接口。普通窗口、面板、自定义内容、输入控件以及任何窗口的最小化、未保存文档和附属对话框仍受保护。图标窗口或内容身份无法确认时保留拦截，不单凭层级或不可聚焦就放行。菜单展开、应用活跃及草稿状态继续单独检查。

下次检查时间只在原流程确有排期且仍启用时显示；暂停和未排期不展示虚构时间。

## 退出协议与发布

退出请求绑定进程、运行版本、随机标识和短有效期。应用回执只含本次请求关联、实例、版本、时间和固定原因代码，不含正文、标题、客户名或内容摘要。两端使用私有普通文件校验与原子回执，拒绝不匹配、过期、损坏或无法确认的数据。

新版回执可附带 `interface_sources`，只允许菜单展开、应用活跃、可见或最小化窗口、对话框、系统标记的未保存文档这五类固定代码。原因、这些代码和检查时间由同一次同步主线程检查生成，退出前重新检查；写回执不另读界面状态。新版读端兼容精确的旧九字段格式及只多这一字段的新格式；缺少该字段表示细分未知，不能当成界面空闲。未知代码、重复项、任意新增字段或与 `interface_in_use` 矛盾的细分均拒绝。请求失效而未取得有效界面判断时省略细分。

进化事项沿原文案补充固定的占用类型，不写窗口标题、稿件内容或客户名称。界面工具没有显示菜单不证明菜单已关闭；实际菜单检查需绑定原生回执、实例和版本。只有细分恰为 `menu_open` 且没有其它原因才可认定菜单独占阻断；混有其它占用时分别保留，允许退出仍须核对原进程消失。

应用在主线程进入原生退出决策点时重新读取本次请求，并再次核对所有输入和界面状态。发布端独立确认原进程确实消失；“允许退出”不等于“已经退出”。每次文件交换及源码提交前再次检查应用是否重开。保留旧调用的 `app_busy` 状态；无强制退出入口。

首次安装仍面对旧版本的退出能力。必须先确认输入安全并正常退出；无法确认就延期安装。候选、配套内核、发布顺序、回滚与安装后行为分别核验，不复用或改指其他聊天的作业和回执，不恢复旧用户数据。

## 回归入口

- `swift test --package-path apps/PersonalAIMonitorMenuBar`：版本、保存顺序、撤销、未知结果、多个表单及占用条件。
- 正式原生资格使用既有 `tools/run-swift-release-tests.sh`，新增状态回归纳入 `Phase2ContextModelsTests` 和版本控制中的精确测试名单；不能以普通构建或部分测试替代。
- `scripts/check-publication-drafts.sh`：编译实际原生状态持有者和退出协调器，在临时目录验证关闭重建、读回完成、隐私撤去、真实菜单栏图标及多屏镜像的受限排除、未登记身份及按钮／普通高层非键窗口／图标内自定义、输入或手势内容和编辑状态仍拦截、菜单展开期间的实际计时回执、菜单解除和最终检查竞态；不触碰正式退出请求或退出正式应用。
- 后台 `tests.test_idle_exit`、`tests.test_activity_confirmations`、`tests.test_context_console`、`tests.test_external_recovery`、`tests.test_project_autonomy`：原读取入口、拒绝及回读、无正文回执、旧版兼容、真实进程条件和中途重开。

正式资格检查仍沿项目既有完整回归、隔离构建、签名、隐私检查及独立审查。以上入口和源码描述不是安装或现场验收回执。

## 交接草稿的来源读取边界

活动与历史问题的交接读取沿原明细入口构造相同的来源过滤卡片，再进行最终展示策略复核。它不再构造整个事项中心，避免无关历史查询拖慢保存回执。标识存在不等于来源获准；缺失、撤回、不可读取及读取期间变化均保留原失败保护。保存前、事务内和回执读取的核对次数、最新版本比较、原20秒读取期限和人工提交保持不变。

十项临时库回归覆盖最新草稿、迟到旧版本、重新读取、恢复空值、来源缺失和撤回、中途策略变化、提交后回读失败与零真实提交。完整发布资格、安装、真实窗口和自然运行分别取证，不以代码或隔离回归代替现场验收。
