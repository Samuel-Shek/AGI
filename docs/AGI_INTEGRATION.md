# AGI 0.6.0 整合说明

产品统一使用 AGI 名称，Bundle ID 保持 app.personalai.monitor，执行文件和原有数据路径保留。临时签名的权限延续需要本机验收。

原生界面通过 CoreRunner 的固定动作连接 activity_mvp.evolution_bridge；短客户端调用同一凭证保护的 127.0.0.1 控制器，不按刷新重建队列。超时和组件故障只影响进化页面。进化库位于现有 core/data/agi-evolution，与 activity.sqlite 分开。

core/evolution 为唯一受维护进化源；基于历史原型 f461eb28146d50ba7b290445f20e544408f09529 导入。Hermes Kanban 是固定源码派生内核，不加载用户 profile、网关或任意工具 worker。未安装新的 launchd 调度。控制器空闲 120 秒退出，停止状态不因重启解除。

AGI 消费者复用既有摘要确认、来源核对和期限。使用不同身份、签名密钥及投递目标，四个 Codex MCP 工具不变。用户操作从 agi-sharing 进入，消费入口只能使用已获准包；提供、引用与本人帮助评价独立。分析只是有界规则整理，不能作为完整 AI 判断或收益证据。任务只留来源引用、期限及决定类型，不保留摘要正文；撤回和过期后的有效状态在每次检查重新核对。

暂停阻止新的本地分析和回放。停止先写持久停机标志，再按组件核对。恢复只解除本地分析暂停，不授权屏幕采集、持续观察、模型或生产写入。用户可继续使用原有记录控制，两个组件权限独立。

安装步骤必须先通过完整 Python、132 项进化测试、Swift 验收、隐私扫描及干净构建。运行 Core 的来源哈希覆盖 evolution 全部发行文件，与候选应用清单一致。受控安装先停止旧进程、保留匹配的应用和 Core、使用 SQLite Backup API 建立一致性本地备份，再替换代码与应用；不迁移 schema 32，不覆盖当前数据。回退配套代码，保留升级后新数据。

升级后的验收包括：原数据和设置保留、无重复后台、独立摘要授权、引用和撤回、暂停与停止、崩溃恢复、界面响应。真实睡眠、屏幕权限、自然使用收益不能由单元测试代替。
